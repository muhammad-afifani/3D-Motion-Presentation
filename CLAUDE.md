# Engine & Turbine Emission Lab

Presentasi web 3D interaktif untuk staf produksi migas: diesel engine, gas engine, turbin generator (single-shaft), turbin kompresor (twin-shaft). Menghubungkan siklus termodinamika → efisiensi → emisi (NOx, CO, CO₂, methane slip) → argumen baku mutu. Bahasa UI: **English default, Indonesia opsional lewat sakelar EN/ID** (Paket D, bertahap); catatan presenter (`content/presenter.json`) tetap **Indonesia** karena itu naskah lisan; nama resmi regulasi tetap Indonesia (lihat Konvensi).

## Stack
Vite + JavaScript ES modules (JSDoc untuk tipe), three.js, vitest. Tanpa backend dan tanpa API eksternal saat runtime. Harus jalan offline lewat `npm run build:offline` + server statis lokal (mis. `npm run preview:offline`; lihat README "Cara presentasi offline"; `file://` tidak didukung karena ES module/Web Worker), dan ter-deploy ke GitHub Pages lewat `.github/workflows/deploy.yml` (`npm run build`, base `/<nama-repo>/`). Semua model 3D prosedural (tanpa file aset berhak cipta). Grafik 2D memakai canvas buatan sendiri atau uPlot.

## Arsitektur (wajib)
Alur data satu arah: `UI control → store.set → derive() → frame → { rig 3D, chart, HUD }`.
- Rig 3D, chart, dan HUD **hanya membaca `frame`**.
- Dilarang menghitung termodinamika/emisi di file `scenes/`, `gfx/`, `charts/`, `ui/`. Butuh perhitungan baru → tambahkan fungsi ke `thermo.js` beserta tes golden-nya.
- Tidak ada angka termodinamika atau emisi yang ditulis langsung (hardcode) di UI.
- Titik di diagram P-V/T-s dan posisi piston/rotor 3D harus berasal dari state yang sama pada setiap frame.

## Aturan model dan akurasi
- JANGAN ubah rumus di `thermo.js` tanpa menambah atau memperbarui tes golden dan menyebutkan alasannya.
- Semua korelasi emisi berlabel **"indikatif"** di UI. Faktor kalibrasi (`ENGINE_NOX_CALIB`, kalibrasi DLN via `calibrateTo`) dan asumsi harus terlihat di panel asumsi (tombol `H`). Faktor ≠ 1 tampil di HUD.
- Level NOx absolut dikalibrasi ke nilai tipikal literatur, bukan data unit. Jangan menyajikannya sebagai prediksi vendor atau data lapangan.
- Model part-load memakai fuel split premix tetap. Jangan menampilkan klaim "CO meledak di twin-shaft". Kalimat yang didukung model: jendela operasi twin-shaft bergeser dan menyempit. Single-shaft menunjukkan "tebing" CO setelah IGV habis.
- Selalu tampilkan basis koreksi O₂ (mis. 15%) dan basis volume (0 °C / 25 °C) di samping angka ppm atau mg/Nm³.
- Limits live in `content/regulations.json` and are never written in code. Values are transcribed from the published tables and carry a `verified` flag. (Pemilik proyek yang mengubah `verified` menjadi `true` per grup setelah dicek ke teks resmi; selama `false`, banner "Transcribed from the published tables…" tampil di halaman Regulations, Scene 6, dan Scene 9.)
- Perbandingan ke limit (chip `Within` / `Above` / `Not modeled` + margin %, jendela operasi) **hanya** lewat jalur regulasi di `thermo.js` (`complianceCheck`; margin < 10 % diberi keterangan "margin is smaller than model uncertainty"): `correctToRefO2Reg` (konstanta 21) dan konversi volume pada basis grup (`toRegulationBasis`, 25 °C). Jalur tampilan (`correctToRefO2`, 20,9) tidak dipakai untuk membandingkan. Chip tidak pernah menyatakan "compliant"/"lulus": teksnya "Model value vs limit (indicative)". Override presenter ditandai "limit: user override"; CO turbin hanya dari isian "permit/OEM value (user input)" (tabel turbin tidak punya limit CO). Site data diutamakan dan ditandai.
- Tidak menyebut vendor, merek, atau tipe turbin tertentu.
- **Satuan tampilan (M13)**: nilai di model, store, dan frame TETAP satuan dasar (`UNIT_DEFS`: Pa, K, W, J/kg, …). Konversi hanya saat menulis angka di lapisan tampilan (HUD, sumbu dan tick grafik, overlay, tabel, kartu bantuan, PNG, jendela presenter) dan hanya lewat fungsi `thermo.js` (`toUnit` dkk.); `model/`, `state/derive*.js`, `state/regulations.js`, `state/store.js` tidak membaca `unitsStore` (dijaga `tests/units.test.js`). **Jalur regulasi tidak terpengaruh**: status chip, margin, dan jendela operasi identik di semua preset (dijaga tes); satuan hanya mengubah cara angka hasilnya ditulis, dengan basis regulasi tetap terlihat. SELISIH suhu dan laju per derajat memakai `toUnitDelta` / `toUnitRate` (tanpa offset; `docs/U_audit_suhu.md`). Basis O₂ dan volume (0 / 25 °C) selalu di samping angka ppmvd / mg/Nm³; basis volume tetap 0 / 25 °C ("Nm³"), basis "scf" tidak dimodelkan; debit hanya debit aktual. Preset US customary tidak mengubah satuan konsentrasi; scene yang menampilkan ppmvd dan mg/Nm³ berdampingan (Scene 4) tetap menampilkan keduanya. Tekanan US ditulis "psia" (semua tekanan model absolut). Legenda suhu: K tetap utama, satuan pilihan di sampingnya (berlaku mulai U3). Contoh hitung di Settings berlabel "Model example (indicative)", dihitung dari model, bukan data unit atau angka vendor. Bendera `UNITS_UI`: seksi Units dan pengaruh satuan MATI di build normal; nyalakan untuk uji dengan `?units=1` di alamat (tersimpan di `etel:unitsUi`) atau `localStorage.setItem('etel:unitsUi','1')`; `?units=0` mematikan lagi.
- Konten Learn dan Chart guide (`content/learn.json`) tidak berisi angka model: angka dibaca dari HUD. Yang boleh hanya definisi satuan, konstanta terbitan bersumber (mis. GWP dari AR6), atau contoh bulat yang ditandai sebagai contoh. Kalimat kejujuran model tetap sama (twin-shaft = jendela operasi bergeser dan menyempit; single-shaft = "cliff" CO setelah IGV habis).
- Isi `content/help.json` mengikuti aturan yang sama dengan Learn: tanpa angka model (validator hanya mengizinkan subskrip kimia, "Scene N", "key X" / "tombol X", dan "3D"), tanpa nama fungsi/konstanta kode dan vendor, korelasi emisi berlabel "indicative" (level absolut dikalibrasi ke nilai tipikal literatur, bukan data unit atau prediksi vendor), basis O₂ dan volume disebut bila membahas ppm / mg/Nm³, chip bukan "compliant"/"lulus". Item yang dipakai di banyak scene berisi kalimat generik tanpa menyebut scene tertentu. Tes: `tests/help.test.js`.
- Tingkat model berlabel di pojok tiap grafik lewat tag **Basis** (`Basis · <level>`): `Ideal` / `Real (component efficiency)` / `Semi-empirical` / `Site data`. Klik tag membuka kartu Basis (level, asal rumus, sumber, asumsi). Tag juga ada di HUD yang menampilkan angka model.

## Aturan referensi (M9)
- Hanya id dari `content/references.json` yang boleh dikutip di UI. Sumber yang belum ada di file itu tampil sebagai **"source to verify"**, tidak pernah dikarang; catat di `toVerify` pada entri `basis.js`.
- Setiap ekspor `thermo.js` wajib punya entri di `src/model/basis.js` (`level`, `refs`, `derivation`, `assumptions`), atau tercatat di `UTILITY` bila hanya helper matematika/gambar (dijaga `tests/basis.test.js`). Mengubah rumus di `thermo.js` berarti memperbarui entrinya.
- Flag `locatorVerified` di `references.json` hanya diubah pemilik proyek setelah mencocokkan bab/persamaan dengan salinan cetak. Selama `false`, halaman References (tombol `?`, alamat `#/references`), kartu Basis, dan sumber di Learn / Chart guide menampilkan "locator not verified" / "to verify", kecuali pengguna memilih **Hide working notes** (Settings ⚙; lihat Konvensi). Label kejujuran model (indicative, tag Basis, basis O₂ dan volume, banner "Transcribed from the published tables…") tidak bisa disembunyikan.
- Nama fungsi/konstanta kode hanya boleh tampil di kartu Basis dan panel asumsi (`H`), tidak di caption, tooltip, atau HUD (dijaga `tests/language.test.js`).
